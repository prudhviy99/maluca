# AI Incident Triage: Data Model

This document describes the implemented Java wire contracts, PostgreSQL schema,
repository semantics, and lifecycle transitions. Flyway migrations V1 through
V5 under `maluca-triage/src/main/resources/db/migration/` are the database
source of truth.

## Storage ownership

`maluca-triage` is the only schema owner. It uses Spring JDBC for operational
tables and Spring AI's `VectorStore` for `runbook_chunks`. PostgreSQL 16 with
the pgvector extension is required. V1 also enables `hstore` and `uuid-ossp`;
V3 enables `pgcrypto` for canonical proposal hashing.

The schema has six application tables:

```text
decisions                         runbook_chunks
    |                                  (independent)
    | aggregated into
    v
incidents
    +----< triage_reports (one per incident)
    +----< policy_proposals
    |          |
    |          +-- optional report_id -> triage_reports
    +----< audit_events
```

Deletes cascade from an incident to its report and proposals. Audit rows retain
their row but set `incident_id` to null. A report deletion sets a proposal's
optional `report_id` to null.

## Shared contracts

### `DecisionEvent` and `DecisionBatch`

`DecisionBatch` is a copied, null-to-empty list of immutable decision events.
`DecisionEvent` ignores unknown JSON fields for producer/consumer forward
compatibility and contains:

| Field | Meaning |
|---|---|
| `eventId` | Idempotency UUID generated by the proxy. |
| `occurredAt` | Proxy-side UTC timestamp. |
| `clientKey` | Resolved proxy key on the wire; normally HMAC-pseudonymized before storage. |
| `method`, `path` | Request method and raw path. The proxy omits the query string. |
| `policyName`, `policyRoute`, `policyMode` | Policy that controlled the request. Unmatched traffic uses `none` for name/route. |
| `tier` | Resolved client tier. |
| `computedAction` | Action selected by scoring, rate limiting, lists, bypass, or Redis fail behavior. |
| `executedAction` | Actual action. Dry-run/observe decisions execute `ALLOW`. |
| `score`, `reason`, `contributions` | Numeric risk score, branch reason, and named contribution map. |
| `dryRun` | Whether enforcement was suppressed. |
| `traceId` | Optional trace correlation string. |

The contributions map is copied and null becomes empty. The contract itself
does not validate field lengths or action values; ingest performs those checks.

### Incident contracts

`IncidentTrigger` records the deterministic condition that opened the row:

- `MITIGATION_SPIKE`
- `CHALLENGE_BLOCK_SURGE`
- `TRAFFIC_VOLUME_SURGE`
- `REDIS_DEGRADATION`
- `MANUAL` (defined but no creator endpoint is implemented)

`Classification` is the later model result and supports `BURST_FLOOD`,
`DISTRIBUTED_FLOOD`, `PATH_SCAN`, `CREDENTIAL_STUFFING`, `LOW_AND_SLOW`,
`REDIS_DEGRADATION`, `FALSE_POSITIVE_WAVE`, and `UNKNOWN`. Confidence is
`LOW`, `MEDIUM`, or `HIGH`.

`IncidentStats` contains the current/baseline shares, score aggregates,
distinct-client/path counts, computed-action histogram, contribution totals,
and bounded top client/path lists. Collection fields are copied and null
becomes empty.

### Report and remediation contracts

`TriageResult` is strict model output (`@JsonIgnoreProperties(false)`) with
classification, confidence, summary, evidence references, citations, and an
optional typed `PolicyPatch`. `TriageReportView` adds persistence metadata, the
retrieved chunk snapshot, valid/fallback status, and validation errors while
deliberately omitting the raw model response.

Each citation is an exact `(chunkId, source, heading)` triple. Each evidence
reference is a `(fact, value)` pair; runtime validation checks that pair against
one selected-field assignment in the serialized incident brief. It also
supports an exact bounded one-level nested JSON map path such as
`action_counts.BLOCK=190`.

`PolicyPatch` permits only:

- exact `policyName` and `route` identity;
- `mode`, `keying`, and `failMode`;
- an algorithm-specific `RateLimitPatch`;
- a partial five-value `BandsPatch`;
- CIDR additions/removals for allowlist and denylist; and
- a rationale.

Null scalar/nested fields mean “leave unchanged”; list fields are copied and
null becomes empty. The shape cannot encode arbitrary YAML, a file path, a
command, or a new arbitrary property.

`ApprovalRequest` binds approval to `proposalId`, `expectedProposalSha256`,
`expectedPolicySha256`, and `expectedIncidentVersion`; `approvedBy` is optional
display/audit context and does not grant authority. `PolicyProposalView`
exposes the full patch, proposal/baseline/target digests, state, timestamps,
and sanitized failure.

## `decisions`

| Column | Type and constraint | Source/semantics |
|---|---|---|
| `event_id` | `uuid PRIMARY KEY` | Proxy-generated idempotency key. |
| `occurred_at` | `timestamptz NOT NULL` | Event time used for windows and retention. |
| `ingested_at` | `timestamptz NOT NULL DEFAULT now()` | Database receipt time. |
| `client_key` | `text NOT NULL` | Normally `client_` plus 40 lowercase hex HMAC characters. |
| `method` | `varchar(16) NOT NULL` | Required and truncated to 16 characters. |
| `path` | `text NOT NULL` | Required and truncated to 512 characters by default. |
| `policy_name` | `varchar(128) NOT NULL` | Required; detector grouping key. |
| `policy_route` | `varchar(512) NOT NULL` | Required route pattern. |
| `policy_mode` | `varchar(32) NOT NULL` | Uppercased and allowlisted at ingest; not enum-constrained in SQL. |
| `tier` | `varchar(64) NOT NULL` | Required. |
| `computed_action` | `varchar(32) NOT NULL` | Uppercased and allowlisted at ingest. |
| `executed_action` | `varchar(32) NOT NULL` | Uppercased and allowlisted at ingest. |
| `score` | `integer NOT NULL CHECK 0..100` | Also checked before insert. |
| `reason` | `varchar(256) NOT NULL` | Required; `redis_down%` is the per-policy fallback input for the Redis rule. |
| `contributions` | `jsonb NOT NULL DEFAULT {}` | Up to 64 bounded-key, finite contributions in `0..1,000,000,000` at ingest. |
| `dry_run` | `boolean NOT NULL` | Enforcement-suppression marker. |
| `trace_id` | `varchar(64)` | Nullable trace correlation. |

Indexes are:

- BRIN on `occurred_at` for time-ordered retention/window scans;
- btree on `(policy_name, occurred_at DESC)`;
- btree on `(computed_action, occurred_at DESC)`; and
- btree on `(reason, occurred_at DESC)`.

Batch insert uses `ON CONFLICT (event_id) DO NOTHING`. The returned duplicate
count is batch size minus inserted rows. A duplicate event does not overwrite
the original.

The decision query API orders newest first and can filter by policy,
pseudonymous client key, **computed** action, inclusive `from`, and inclusive
`to`. Its result limit is clamped to 1–200. The direct decision endpoint does
not impose a maximum time span; MCP performs a separate 24-hour validation.

Signal breakdown expands `contributions` with `jsonb_each_text`, sums numeric
values by signal, orders descending, and caps the result at 64 signals. The API
requires a positive window no larger than 24 hours.

## `incidents`

| Column | Type and constraint | Semantics |
|---|---|---|
| `id` | `uuid PRIMARY KEY` | Random incident ID. |
| `opened_at` | `timestamptz NOT NULL` | First anomalous poll. |
| `closed_at` | nullable `timestamptz` | Set by detector resolution or operator dismissal of a terminal triage failure. |
| `last_active_at` | `timestamptz NOT NULL` | Updated on a matching anomalous poll. |
| `policy_name` | `varchar(128) NOT NULL` | Debounce/uniqueness key. |
| `policy_route` | `varchar(512) NOT NULL` | Route observed in the aggregate. |
| `trigger` | `varchar(64) NOT NULL` | `IncidentTrigger` name. |
| `status` | `varchar(32) NOT NULL` | `IncidentStatus` name. |
| `stats` | `jsonb NOT NULL` | Serialized `IncidentStats`. |
| `version` | `bigint NOT NULL DEFAULT 0` | Optimistic concurrency value. |
| `triage_lease_id` | nullable `uuid` | Random fencing token owned by the current worker. |
| `triage_claimed_at` | nullable `timestamptz` | Lease age; constrained to be null exactly when the lease ID is null. |
| `triage_attempts` | `integer NOT NULL DEFAULT 0` | Total claims, including manual retries. |
| `triage_next_attempt_at` | nullable `timestamptz` | Earliest scheduled eligibility after backoff. |
| `triage_failure` | nullable `text` | Last sanitized worker/lease failure, capped to 2,000 characters by the repository. |

A partial unique index on `policy_name` applies while `closed_at IS NULL` and
status is not `RESOLVED`, `DISMISSED`, or `APPLY_FAILED`. Consequently
`APPLY_INDETERMINATE` continues to block a second active incident. There are
additional indexes on descending `opened_at`, `(status, opened_at DESC)`,
eligible retry time, and stale lease time. `TRIAGE_FAILED` intentionally
remains inside the unique active set until an authorized retry succeeds or an
operator dismisses the exact reviewed terminal version.

### Implemented lifecycle

```text
detector                     worker/report                  human apply
   |                              |                              |
   +-> OPEN --eligible claim--> TRIAGING --fenced save------> TRIAGED
         ^                         |                              |
         |                         +--failure/fallback + backoff--+
         |                         |
         |                         +--attempt budget-------> TRIAGE_FAILED
         |                                                    |       |
         +------------------- explicit operator retry <-------+       +--> DISMISSED
         |                                                        |
         |                                      CAS approval ----> APPROVED
         |                                                        |
         |                                      success ----------> APPLIED
         |                                      safe/compensated failure -> APPLY_FAILED
         |                                      uncertain state ----> APPLY_INDETERMINATE
         |                                                               |
         |                            verified target/baseline ----------> APPLIED/APPLY_FAILED
         |
         +---- a later retry after an agent dependency failure

OPEN, TRIAGED, or APPLIED --inactive for resolve-after--> RESOLVED
```

Important as-built details:

- The opening detector snapshot is frozen in `stats`. A continuing anomaly
  updates only `last_active_at` (not the reviewed optimistic `version`) for any
  row the repository considers active, including `TRIAGING`, `TRIAGE_FAILED`, `TRIAGED`,
  `APPROVED`, `APPLIED`, and `APPLY_INDETERMINATE`.
- Only a gate-valid report finishes as `TRIAGED`. A validator-generated
  fallback is persisted under the fenced lease, then the incident returns to
  `OPEN` with backoff or reaches `TRIAGE_FAILED` at the attempt limit.
- A claim carries a random lease UUID and timestamp. Startup and every worker
  poll reclaim stale leases; report writes lock and verify the UUID before any
  upsert, fencing a late worker.
- Failures use capped exponential backoff and `triage_next_attempt_at`. The
  third failed claim by default becomes `TRIAGE_FAILED`, which scheduled work
  will not select. An authorized caller can retry it explicitly through the
  manual triage endpoint.
- Storing a proposal does not change incident status.
- An operator can dismiss only an open `TRIAGE_FAILED` row using its exact
  reviewed version plus a bounded reason. The transition closes the row and is
  audited; scheduled work cannot dismiss incidents.
- Automatic resolution selects inactive `OPEN`, `TRIAGED`, and `APPLIED` rows.
  It deliberately leaves `TRIAGING`, `TRIAGE_FAILED`, `APPROVED`, and
  `APPLY_INDETERMINATE` transitions alone.
- `setStatus` increments `version` without an expected-version predicate.
  Claim and approval transitions use optimistic predicates.

The detector method is transactional and first attempts
`pg_try_advisory_xact_lock` with a fixed key. PostgreSQL releases that lock at
transaction end. The partial unique index and `ON CONFLICT DO NOTHING` remain
the final database-enforced single-active-row invariant.

## Incident stats computation

Current-window aggregation groups only by `policy_name` and selects
`MAX(policy_route)` for the route. It calculates:

- total decision count;
- computed actions outside `ALLOW`/`OBSERVE` as mitigated;
- computed `CHALLENGE` plus `BLOCK` count;
- decision reasons matching `redis_down%`;
- average/max score; and
- distinct client-key/path counts.

Baseline aggregation calculates total and mitigated count over the preceding
baseline interval. Snapshot queries then calculate a full computed-action map,
the top contribution totals, top pseudonymous clients, and top paths. Top lists
and contribution totals use `top-value-limit` (10 by default). The configured
decision sample limit (50) is applied later when building the agent brief and
is not persisted in `stats`.

The detector can append a synthetic aggregate from Prometheus's global
`maluca_redis_errors_total` increase. That incident uses policy
`__maluca_redis__`, route `/_maluca/redis`, and records the increase as the
`redis_errors` contribution. Ordinary per-policy aggregates still derive
`redisErrors` from `redis_down%` decision reasons and provide the fallback when
the global signal is unavailable. An unknown Prometheus result prevents
automatic resolution of an existing synthetic Redis incident.

## `triage_reports`

| Column | Type and constraint | Semantics |
|---|---|---|
| `id` | `uuid PRIMARY KEY` | Generated on first insert and preserved on report upsert. |
| `incident_id` | FK, `UNIQUE`, `ON DELETE CASCADE` | Exactly one current report per incident. |
| `created_at` | `timestamptz DEFAULT now()` | Generation time. |
| `model`, `prompt_version` | bounded text, non-null | Configuration recorded with the result. |
| `classification`, `confidence`, `summary` | non-null text | Parsed/validated output or code fallback. |
| `evidence`, `citations` | `jsonb`, default arrays | Accepted lists. |
| `retrieval_context` | `jsonb NOT NULL`, default array | Exact retrieved `RunbookChunkView` list used for generation and citation validation. Added by V2. |
| `proposed_patch` | nullable `jsonb` | Patch returned in model output; not itself a proposal row. |
| `valid` | `boolean NOT NULL` | `true` for gate-passing output, `false` for fallback. |
| `validation_errors` | `jsonb`, default array | Final failure reasons. |
| `raw_response` | `text NOT NULL` | Last raw model response; empty when none exists. |

An `ON CONFLICT (incident_id) DO UPDATE` overwrites the report projection while
preserving the row's primary key. The external JSON API omits `raw_response`
but returns `retrievedChunks`; each entry includes logical ID, source, heading,
content, and similarity. The Markdown renderer shows accepted citations rather
than the complete retrieval context.

Because the content snapshot is stored with the report, later runbook
re-ingestion does not erase what the model saw. The snapshot does not include a
separate embedding-model version or embedding vector.

A `valid=false` fallback row is diagnostic output, not a completed triage
state. It can coexist with an incident returned to `OPEN` or moved to
`TRIAGE_FAILED`, and a later attempt replaces the one-report projection.

## `policy_proposals`

| Column | Type and constraint | Semantics |
|---|---|---|
| `id` | `uuid PRIMARY KEY` | Proposal identifier. |
| `incident_id` | FK `ON DELETE CASCADE` | Owning incident. |
| `report_id` | nullable FK `ON DELETE SET NULL` | Report row from which the proposal originated. |
| `report_created_at` | nullable `timestamptz` | V5 copy of the exact report generation time, paired with `report_id` for provenance. |
| `created_at`, `created_by` | timestamp/text | Proposal audit origin. |
| `patch` | `jsonb NOT NULL` | Typed `PolicyPatch`. |
| `proposal_sha256` | `varchar(64) NOT NULL` | Lowercase SHA-256 of PostgreSQL's canonical `patch::text`; added by V3 and recomputed at apply/reconcile time. |
| `policy_sha256` | `varchar(64) NOT NULL` | Baseline policy-file hash captured at proposal time. |
| `target_policy_sha256` | nullable `varchar(64)` | Exact patched-file digest computed before approval and stored with `APPROVED`; added by V3. |
| `status` | `varchar(32) NOT NULL` | Includes `PROPOSED`, `APPROVED`, `APPLIED`, `APPLY_FAILED`, `APPLY_INDETERMINATE`, and `REJECTED_STALE_PROVENANCE`. |
| `approved_at`, `applied_at` | nullable timestamps | Workflow milestones. |
| `failure` | nullable text | Apply failure truncated to 4,000 characters. |

Multiple pending proposal rows are allowed. Apply never chooses one by
recency: the request names the exact `proposalId`, and the repository requires
that row to be `PROPOSED` for the path incident. Approval also compares the
request's proposal digest and baseline file digest, recomputes the digest from
stored JSONB, and checks the current incident version. Proposal creation
requires a current valid report and stores both that report's ID and its
generation timestamp. A later report generation quarantines older pending rows
as `REJECTED_STALE_PROVENANCE`; approval joins against the still-current valid
report and cannot select a quarantined row.

V3 also adds an index for `PROPOSED`/`APPROVED` rows and retains
`APPLY_INDETERMINATE` incidents in the one-active-policy invariant. Read APIs
are `GET /api/v1/proposals/{id}` and
`GET /api/v1/incidents/{id}/proposals?limit=20`; the latter orders newest-first
and clamps its limit to 1–100.

V5 requires exact report-generation provenance for `PROPOSED` rows and makes a
repeated `(report generation, patch digest, actor)` submission idempotent.
Pending rows created before that provenance existed are retained for audit as
`REJECTED_STALE_PROVENANCE`; they cannot be approved.

## `audit_events`

Audit rows have a `bigserial` ID, occurrence time, nullable incident FK, actor,
action, and JSONB details. Implemented action names are:

- `POLICY_PROPOSED`
- `POLICY_APPROVED`
- `POLICY_APPLIED`
- `POLICY_APPLY_FAILED`
- `POLICY_APPLY_INDETERMINATE`
- `POLICY_RECONCILED_TARGET`
- `POLICY_RECONCILED_BASELINE`
- `POLICY_RECONCILIATION_REFUSED`
- `INCIDENT_TRIAGE_FAILURE_DISMISSED`

Approval details include proposal ID, proposal digest, and target policy
digest. Successful apply details include proposal ID, previous/new hashes, and
the backup path. Failure/indeterminate details contain a bounded sanitized
reason. The table is indexed by `(incident_id, occurred_at DESC)`. There is no
audit-query API in the current controller surface.

## `runbook_chunks`

The table uses Spring AI's canonical pgvector shape:

| Column | Type | Semantics |
|---|---|---|
| `id` | `uuid PRIMARY KEY DEFAULT uuid_generate_v4()` | Physical document ID; ingestion normally supplies a deterministic ID. |
| `content` | `text NOT NULL` | Title plus one H2 section. |
| `metadata` | `json NOT NULL` | `chunk_id`, `source`, `heading`, `sha256`, `embedding_model`, and `trusted=true`. |
| `embedding` | `vector(768) NOT NULL` | Ollama embedding. |

An HNSW index uses `vector_cosine_ops`. A unique expression index on
`metadata->>'chunk_id'` makes the logical ID unique.

Ingestion is serialized across replicas with a transaction-scoped PostgreSQL
advisory lock. Spring AI's `VectorStore.add` performs an upsert for new and
changed documents; a text-digest or embedding-model-identity change forces a
fresh vector while retaining the physical UUID. These upserts
finish before truly obsolete IDs are deleted, and both operations run in one
application transaction. A failure rolls back the replacement and retains the
last committed corpus. Because the table is dedicated to trusted runbooks,
ingestion deletes every row absent from the desired corpus; retrieval rejects
missing/untrusted/stale-model metadata instead of citing it.

## Retention and privacy semantics

Only decisions have an implemented scheduled retention job. At minute 17 of
every hour by default, it deletes rows whose **occurrence time** is older than
seven days. It does not use `ingested_at`.

No scheduled retention exists for incidents, reports, raw responses,
proposals, audit events, runbook chunks, or policy backups. Policy backups are
instead pruned after a successful apply to the configured count (10 by
default); a value below one disables pruning rather than backup creation.

Default client-key pseudonymization is deterministic HMAC-SHA-256 with the
first 20 bytes rendered as 40 hex characters. Keeping the HMAC key stable
preserves correlation; rotation creates a deliberate correlation boundary.
Pseudonymization does not make paths, trace IDs, tier, policy, reports, or model
raw output anonymous.

The ingest contract carries no request body, cookies, authorization headers,
passwords, or challenge tokens. Those values should not be added to the event
schema.

## Database constraints versus Java validation

The database enforces keys, nullability, score range, vector dimension, the
one-active-policy index, proposal/baseline/optional-target SHA-256 shapes,
exact report-generation provenance for pending proposals, per-generation
proposal deduplication, a non-negative triage-attempt count, and paired
lease-ID/timestamp nullability.
It does not define enum/check constraints for action, status, trigger,
classification, mode, or proposal status. Normal writes rely on Java
validation and enum serialization.

Similarly, JSON structure is controlled by Java records and repositories, not
JSON Schema constraints in PostgreSQL. Direct SQL writes can violate
application-level invariants and are not a supported integration path.
